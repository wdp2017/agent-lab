## 13 周后拿什么证明

原则：本仓库可运行、README 写清怎么跑、指标都是实测值并注明测法；不用前公司的代码、协议或数据。下面的数字一律写「待实测」，做出后再填。

**作品 A：AI 板书 Agent（优先保证质量）**

- 跑通「拍照或截图 → VLM 识别题目 → 结构化 JSON → 分步讲解 → 渲染指令 → 流式上墙」。
- 验收（待实测）：端到端成功率（计划方向是小样本先跑通，再扩到更大题集）、结构化解析成功率、讲解可用率（人工评分）、首字可见延迟、失败时能否定位到环节。
- 交付：GitHub、README、可复现启动方式、3 分钟演示视频。

**作品 B：教育 RAG + 多 Agent 批改**

- 教材知识库问答（解析、切分、检索、带引用生成、无据拒答）+ 批改编排（先证明 2 个角色比 1 个强）。
- 验收（待实测）：Recall@5、答案准确率、拒答率、与人工批改的一致率；若做了路由或缓存，再补充成本和质量对照。
- 交付：评测集与基线 / 消融说明、可部署服务、演示。

**作品 C：Agent Trace 可视化**

- 记录一次 Agent 运行的 span（输入、输出、耗时、token、工具调用、错误），用节点图 + 时间轴回放，并支持失败注入。
- 验收（待实测）：能否据此定位一次失败或一次慢调用；不预填「排障从 X 分钟降到 Y 分钟」。
- 时间不够时，降级为作品 A 的子页面，但必须有。技术实现不强制 React，优先把问题看清楚。
