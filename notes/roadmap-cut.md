# 路线图取舍

> 对照 13 周学习看板（`agent转型方案/build_dashboard.py` 的 `WEEKS`，开营日 2026-11-13）逐项标注：必做 / 选做 / 跳过。
> 判断标准：对目标岗位（AI 应用开发 / Agent 开发）面试的价值、对作品 A/B/C 是否阻塞、是否复用我已有的前端与教育场景经验，以及时间有限（学习主线优先，副业最多约占 20%）。
> 看板原计划按「全职冲刺、每周 30 小时以上」排期；若实际每周只能投入约 20 小时，优先砍「输入」，**主攻不砍**。内容只复用当周已经做过的事，不反向占用学习时间。

## 砍掉 / 降级了什么、为什么

这次裁剪的核心不是「少学一点」，而是把 13 周从「全量教程清单」收回「能拿去面试的三条作品线」。

砍掉或明确不走的，主要是三条岔路：第一，React / Next.js 系统学习，这和我已经选定的 Python / FastAPI Agent 路线重复抢时间，我也没有要把前端框架当成转型主线；第二，训练、微调、推理引擎这类算法向内容，投入再大也很难在三个月内变成我的比较优势；第三，课程全量录制、多平台运营和各类变现实验——它们可以复用学习过程，但不能反过来变成主线。

降级的，是所有「锦上添花」的工程：ToT / Reflection 深挖、HyDE 与 NLI 全做、多种多 Agent 模式、完整 MCP 与安全专题、四个批改角色一次做满、独立的研究助手产品、为 Trace 专门补一套 React。这些东西有价值，但只在主线（手写 Agent → RAG 基线 → LangGraph → 作品 A/B，以及必须存在的 Trace 可视化）跑通之后才加。作品 C 允许形态降级，不允许缺席。

另外，看板和简历稿里出现过的目标数字（例如首字延迟从 4 秒到 1.2 秒、准确率从 72% 到 89%、成本下降 70%）一律不提前写进仓库。那是验收方向，不是已经发生的结果。
